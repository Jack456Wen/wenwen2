# Distance Tick Optimizer（Forge 1.20.1）

实体距离优化模组，同时支持服务端停 tick、客户端隐藏和客户端停 tick，保留原工程 mod ID `wenwen2`。

## 安装和配置

将 `build/libs/wenwen2-1.1.1.jar` 放入 mods；单人游戏安装在客户端即可同时优化内置服务器和绘制。专用服务端可独立安装，但隐藏与客户端停 tick 需要客户端也安装。COMMON 配置不向远程客户端同步，多人游戏需自行保持参数一致。
首次启动自动生成带中文注释的 `config/wenwen2-common.toml`，无需手动复制示例。配置键名和枚举值保留英文，便于兼容已有配置。
使用 Forge COMMON 配置系统；修改后由 Forge 文件监视器重载，重启也会加载。实体标签随数据包重载生效。

默认暂停距同维度所有非旁观玩家超过 64 格的非玩家实体，使用三维欧氏距离；恰好 64 格正常 tick。
默认 `distanceMode = "SPHERE"` 保持已有配置行为。改为 `"CYLINDER"` 后使用 `horizontalDistance`（默认 64）和 `verticalDistance`（默认 32），须对同一位玩家同时满足水平半径与垂直高度差条件，边界也正常 tick；此时 `activationDistance` 不参与判断。
默认 `protectDying = true`，死亡过程中的生物继续 tick，避免死亡动画和清理被冻结。
掉落物、矿车、模组实体都在处理范围内。默认 `protectProjectiles = true`，弹射物在客户端和服务端均继续 tick，并保留显示和推挤，不受距离冻结影响，避免卡在空中。匹配原版 `Projectile` 及其模组子类；未继承该类的模组弹射物需加入白名单。此保护不强制加载区块，也不扩大原版网络追踪范围。其他实体在客户端进入范围后恢复绘制和本地 tick；服务端恢复受冻结检查间隔影响，无补 tick。
只有原版已加载且可 tick 的区块中的实体受处理，不强制加载区块。

白名单支持 `minecraft:villager`、`create:*`、`#minecraft:raiders` 等实体 ID、模组命名空间、实体类型标签。
未知实体 ID 不会导致启动失败；检查拼写后会在实体注册时自然匹配。

## 兼容性和行为

服务端在 `ServerLevel.tickNonPassenger` 入口使用可取消 Inject，不覆盖整个方法，不改变实体存储、区块加载或网络追踪。客户端在实体 tick 和绘制入口过滤；可选推挤限制拦截原版 Entity 与矿车的实体推挤入口。
白名单规则预解析缓存，逐实体距离比较不求平方根、不为每个实体构造玩家列表。每个维度每 tick 首次需要距离判断时更新玩家位置快照，复用数组；最多 128 位有效玩家时直接扫描，更多玩家时按激活半径划分水平网格，只查询周围九个格子，并用精确距离判断。玩家集中在一起时仍可能退化为逐玩家扫描。
快照在下一 tick 更新；其他模组若在同一 tick 的实体处理途中改变玩家位置、维度或旁观状态，可能到下一 tick 才影响后续实体。关闭间隔检查时不执行冻结调度；缓存直接附在实体上，不再查询全局弱引用实体表。
配置加载和重载时生成不可变快照并预计算距离平方，逐实体判断无需再读取 Forge 配置值。白名单匹配结果按实体类型缓存，配置或实体标签重载后换用全新缓存，避免陈旧匹配结果。

默认 `delayFrozenChecks = true`、`frozenCheckInterval = 5`，减少已冻结实体的距离检查。间隔范围为 1～200 tick；默认 5 在 20 TPS 下约 0.25 秒，低 TPS 下实际等待更长。关闭后每 tick 判断。开启后玩家靠近/传送到附近可能等待最多一个间隔恢复，正常运行实体仍每 tick 判断。死亡、白名单、骑乘等保护条件仍每 tick 判断；配置/标签重载、实体位置或维度变化会使旧冻结判断失效。调度使用世界游戏时间和实体 ID 分散检查，相同 tick 冻结的实体不会全部在相同 tick 重查。实体缓存原地复用，无每次冻结检查的记录对象分配；不写入存档，实体卸载后随实体回收。

默认 `hideDistantEntities = true`、`freezeClientEntities = true`，客户端使用本地玩家和相同距离参数，白名单及受保护实体继续显示、更新。模型、阴影、名称和实体火焰绘制一起跳过；独立粒子、声音、方块实体和其他模组独立绘制不受影响。每个实体每游戏 tick 缓存一次客户端判断，玩家或实体位置变化会刷新。客户端旁观者不执行距离隐藏；当前摄像机实体也始终保留。标准移动/传送包仍处理，冻结时将网络位置立即应用，避免等待已暂停的插值 tick；这会使远处移动直接跳转。模组自定义同步/动画若不兼容，可单独关闭客户端停 tick。

默认 `maintainNaturalDespawn = true`，冻结生物的非持久化、启用 AI 的空闲计时继续推进。Forge 1.20.1 的自然消失检查本来就在 tick 注入点之前，每 tick 保留执行；没有额外调用或强制删除，也不调整刷怪上限。持久化生物及 NoAI 生物不增加此计时。

`disableFrozenPushing = false` 默认关闭；开启时只禁止冻结实体参与原版实体间推挤，不设置 `noPhysics`，保留方块碰撞、攻击命中和弹射物命中。会改变重叠和运输行为，模组自定义推挤可能绕过原版入口。
`limitNaturalSpawns = false` 默认关闭；开启时在 Forge 自然生成位置检查中拒绝范围外的 NATURAL 生成，白名单及受保护实体例外。不拦截存档加载、区块初始生成、刷怪笼、繁殖、指令、掉落物和机器物品。它改变刷怪分布，不能消除已经生成的实体，也不能省掉所有前置刷怪尝试。

升级保留旧配置值，不强制把旧 `delayFrozenChecks = false` / `frozenCheckInterval = 10` 改掉；如需新默认值，请手动更新这两个键。示例配置给出默认设置；`config-examples/wenwen2-local-performance.toml` 则开启全部选项。
玩家始终正常 tick。骑乘链、被拴住的生物、进入传送门和传送冷却中的实体始终正常 tick。
默认保护驯服动物、马以及不能切换维度的实体（原版 Boss）；模组 Boss 未必符合该条件，需要白名单。
命名保护默认关闭；可设置 `protectNamed = true`。`scope` 可改为 `MOBS_ONLY`。

冻结会暂停寿命、移动、AI、熔断/爆炸倒计时、状态效果等依赖实体 tick 的行为。
远处农场、矿车运输、掉落物消失和依赖实体的机器因此可能停运，按整合包玩法将对应实体加入白名单。
方块实体不在此模组处理范围内。其他模组通过世界事件独立驱动的逻辑仍可能运行。
其他取消/重写同一实体 tick 入口的优化模组须组合验证；不保证所有整合包零冲突。

## 构建和验证

使用 Java 17：`./gradlew.bat build`。产物经过 `reobfJar` 重映射。
已在本工程 Forge 47.1.3 上完成编译、打包及注入目标映射检查。
独立开发测试源位于 `src/gametest`，不进入发布 JAR。`./gradlew.bat runGameTestServer` 在独立 `run-gametest` 目录验证服务端注入、边界恢复、白名单重载、保护条件、空闲计时、推挤开关和自然生成类型过滤。
客户端画面、模组实体兼容性和 FPS/MSPT 收益仍需在实际整合包中验证。打包可使用 `./gradlew.bat assemble`，不运行测试。

整合包实测建议：在已加载区块中放置生物、掉落物、弹射物和矿车，离开/返回距离边界，验证暂停/恢复；
验证两个玩家、不同维度、旁观模式、无人维度；验证白名单三种格式和配置重载；
验证坐骑、拴绳、宠物、Boss 和传送门；最后与整合包现有优化模组一起运行并比较服务端 MSPT。
